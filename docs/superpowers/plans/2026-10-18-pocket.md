# POCKET Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. The owner approved proceeding with this app and repository; execute inline.

**Goal:** Deliver a genuine unsigned iPhone IPA for a playable finger-drumming course.
**Architecture:** A native SwiftUI shell embeds a UIKit multitouch instrument. A small C++ kernel owns precomputed sounds, timestamped voice rendering, and deterministic assessment; Swift owns lessons, transport, MIDI, persistence, and sharing.
**Tech Stack:** Swift, UIKit, SwiftUI, AVAudioEngine, Core MIDI, C++17; no app dependencies.
**Spec:** `docs/superpowers/specs/2026-10-18-pocket-design.md`

## Global Constraints
- iPhone first; deployment target iOS 17; portrait and landscape; touch targets at least 44 points.
- All 24 original lessons and both original kits available offline.
- Raw performances remain unquantized; MIDI velocity is distinguished from simulated touch dynamics.
- No merge; work only on `codex/pocket-finger-drumming`.
- First arm64 unsigned IPA before extended native tests; each validation stage limited to 600 seconds.

## Review Focus
- Rapid and simultaneous inputs must retain distinct sound events and receive no duplicate assessment credit.
- A canceled count-in, interruption, or route change must not leave old scheduled notes or award a pass.
- Dense subdivisions and phrase boundaries must not match a strike to more than one note.
- Empty, corrupt, or interrupted saves must preserve completed work and expose recovery.
- Compact landscape and large teaching text must leave the playing controls reachable.

### Task 2: Course and player

**Interfaces:** `Lesson` owns role-based musical events and teaching steps; `Session: ObservableObject` owns transport and assessment; `AudioEngine` wraps Task 1; `MIDIInput` produces note/velocity/timestamp events; `TakeExporter` produces valid MIDI and WAV files.
- [ ] Add course checks for exactly 24 unique lessons, valid bar ranges/roles, and the last unit's eight-bar performance.
- [ ] Implement clock-based count-in, look-ahead scheduling, isolated parts, looping, prompt fading, ear-only recall, wait mode, silent bars, per-route calibration, and completion criteria.
- [ ] Implement atomic JSON persistence, user-controlled tempo suggestions, MIDI Learn/disconnect, velocity-aware assessment, saved takes, and native exports.
- [ ] Validate course structure and generated file formats with real exported files in the macOS check after the first IPA.
